# ByeAI v1.4 — Design Spec

**Date:** 2026-07-11
**Status:** Draft for user review

## Goals

Ship extension v1.4 to the Chrome Web Store together with the infrastructure migration off `byeai.tech`:

1. **Infra migration** — new cheap domain for the API only; website + privacy policy served free from `https://nottoobright.github.io/ByeAI/`.
2. **Bug fixes** — the batching/error-caching/mutation-churn/dead-feedback bugs found in the v1.3 review.
3. **Features** — Shorts support (filter + popup flagging), placeholder bars for community-hidden videos, personal whitelist, toolbar badge count.
4. **Server** — configurable flag-threshold floor to fix the cold-start dead end.

## Non-goals (deferred to v1.5+)

- Curated/importable channel blocklists (F4).
- "Why was this hidden?" detail panel (F5) — the placeholder's menu links can grow this later.
- Onboarding page, dark mode, options-page redesign, Firefox port.
- `/flags` N+1 query optimization (irrelevant at current scale; revisit at >1k users).

## Decisions already made with the user

- Cheap domain is for the **API endpoint only** (`api.<newdomain>` → Oracle VPS `152.69.161.151`). Website stays on github.io. Oracle hosting is kept.
- **Placeholder bars appear only for community-hidden videos** (consensus flags and flagged channels). Videos the user flagged themselves stay silently hidden — they already decided.
- **Shorts support = feed filtering + popup/context-menu flagging.** No button injected into the Shorts player (fragile DOM).

## 1. Shared config (`constants.js`, new file)

Single source of truth for values currently duplicated across 5 files:

```js
// constants.js — loaded before every other extension script
globalThis.BYEAI = {
  API: 'https://api.<NEWDOMAIN>',   // wired in once the domain is purchased
  CATS: [
    { id: 'ai-general',   label: 'AI-General',          desc: 'AI used throughout' },
    { id: 'ai-script',    label: 'AI-Script',           desc: 'AI-written content' },
    { id: 'ai-thumbnail', label: 'AI-Image/Thumbnail',  desc: 'AI-generated images' },
    { id: 'ai-music',     label: 'AI-Music',            desc: 'AI-generated audio' },
    { id: 'ai-voice',     label: 'AI-Voice-over',       desc: 'Synthetic voice' },
    { id: 'deepfake',     label: 'Deepfake/Video',      desc: 'AI-manipulated video' },
    { id: 'other',        label: 'Other',               desc: 'Other AI usage' }
  ]
};
```

Wiring:

- `manifest.json` content_scripts: `"js": ["constants.js", "contentScript.js"]`.
- `popup.html` / `options.html` / `stats.html`: `<script src="constants.js"></script>` before their own script.
- `background.js` is a module: `import './constants.js';` (side-effect import; the file only assigns `globalThis.BYEAI`).

`manifest.json` `host_permissions` becomes `https://api.<NEWDOMAIN>/*`.

## 3. Bug fixes

| # | Fix | Detail |
| --- | --- | --- |
| B1 | Batch `/flags` and `/channels` requests | Chunk ID lists to ≤100 per request (server `MAX_IDS`), sequential requests per chunk. |
| B2 | Stop caching failures as "not flagged" | On fetch failure/429: leave entries unknown, set a global 30 s backoff (respect `Retry-After` when present) before the next attempt. Add an `inFlight` set so concurrent scans don't re-request the same IDs. |
| B3 | Kill the inline-button mutation loop | `injectInlineButton()` becomes idempotent: tag the button with `dataset.vid` + `dataset.state`; only (re)create when missing, detached, or stale. No more remove-and-recreate every 200 ms scan. |
| B4 | Resurrect score feedback; remove dead code | `sendVote()` returns the parsed response JSON (or `null`); `flagMultiple` passes the first vote's response through the `videoFlagged` broadcast so the "Score: X/threshold" toast works. 409 → toast "You already flagged this video." Delete the unused `case 'flag'` handler. |
| B5 | No-op Undo link | `videoUnblocked` toast gets `null` instead of `() => {}`. |
| B6 | Local-time stats days | `todayKey()` (background) and `lastNDays()` (stats page) both use local-date formatting instead of UTC `toISOString()`. Existing UTC-keyed history is left as-is (off-by-one on old days is acceptable). |
| B7 | Category duplication | Solved by `constants.js` (§1). |
| B8 | YouTube DOM drift | Add `yt-lockup-view-model` (and Shorts containers, §4) to tile selectors alongside existing `ytd-*-renderer` ones; manual verification pass on current YouTube home/search/watch/sidebar. |
| B9 | Dead i18n | Delete `i18n.json` and the `web_accessible_resources` block from the manifest. |
| B10 | Drop `downloads` permission | Options-page export uses a temporary `<a download>` click instead of `chrome.downloads`. One less permission at store review. |

## 4. F1 — Shorts support

- `getVid()` (both copies → shared behavior): also parse `/shorts/<11-char-id>` pathnames. Shorts IDs are ordinary video IDs; the server needs no schema change.
- Tile scanning: include Shorts anchors (`a[href*="/shorts/"]`) and containers (`ytm-shorts-lockup-view-model`, `ytd-rich-item-renderer`, `ytd-reel-item-renderer`) in the scan/hide pipeline. Hidden Shorts follow the same placeholder rules (§5) where layout permits; inside dense Shorts shelves the placeholder falls back to silent hide if the bar can't fit sanely (implementation detail, verified manually).
- `getCurrentVideoId()` and the popup's URL check recognize `/shorts/` pages, so the popup flag UI works while watching a Short. Context menu already works via `getVid` on link URLs.
- View counts: the Shorts player DOM doesn't expose a reliable count, so Shorts flags submit `viewCount: 0`. **Server change:** perform the YouTube API view-count lookup whenever `viewCount == 0` (today it only does so for `thumbnail`/`context_menu` sources). Quota is already protected by the existing daily cap + circuit breaker + 100 000 fallback.

## 5. F2 — Placeholder for community-hidden videos

Behavior (community consensus hides and flagged-channel hides only):

```text
┌─────────────────────────────────────────────┐
│ 🚩 Hidden by ByeAI · AI-Voice  [Show][Always]│
└─────────────────────────────────────────────┘
```

- The original tile gets `display:none`; a slim bar (~36 px, rounded, subtle translucent background so it works on YouTube light & dark themes) is inserted as its previous sibling. Tiles are tagged (`dataset.byeaiHidden`) so re-scans don't double-insert.
- Label shows the flag category; channel-based hides show `Channel flagged · <category>`.
- **[Show]** — reveal this tile for the current session only.
- **[Always]** — add the video (or channel, for channel hides) to the whitelist (§6), then reveal.
- Options toggle: **"Show placeholders for community-hidden videos"** — default ON; OFF restores today's silent hiding.
- Locally-flagged videos (`category: 'local'`) never get a bar.
- Cleanup: bars are tracked next to their tiles in `hiddenTiles` so unflag/undo removes both.

## 6. F3 — Personal whitelist

- Storage: `whitelist: { videos: string[], channels: string[] }` in `chrome.storage.local`.
- Precedence: **own blocklist (`blockedIds`) > whitelist > community flags.** The whitelist overrides community/channel hides only; a user's own flags are managed via the existing Unhide button.
- Content script loads the whitelist at startup and reacts to `storage.onChanged`; `shouldHideVideo` / `shouldHideChannel` return `false` for whitelisted entries.
- Options page gains an "Always show" section listing whitelisted videos/channels with remove buttons. Entries are added via the placeholder's **[Always]** action.
- Import/export includes the whitelist alongside `blockedIds` and `banCategories`.

## 7. F6 — Toolbar badge

- Content script reports the number of distinct videos currently hidden on the page (by any mechanism: own flag, community flag, channel flag; placeholder-hidden counts as hidden) to the background after each scan, debounced and only on change: `{ type: 'updateBadge', count }`.
- Background: `chrome.action.setBadgeText({ text: count > 0 ? String(count) : '', tabId: sender.tab.id })`; badge color `#dc3545` set once at startup.

## 8. Server changes

- `calculate_threshold` floor becomes `int(os.getenv('VIDEO_THRESHOLD_FLOOR', 15))`; `CHANNEL_FLAG_THRESHOLD` becomes `int(os.getenv('CHANNEL_FLAG_THRESHOLD', 10))`. Production `.env` sets both to **3** for the cold-start phase; raise as the user base grows. Tests cover the env override.
- View-count lookup on `viewCount == 0` regardless of flag source (§4), with tests (mocked `youtube_service`).
- `/health` version string bumped to match the release.

## 9. Release checklist (v1.4)

1. `manifest.json` version → `1.4`.
2. Build `ByeAI_v1.4.zip` containing only: `manifest.json`, `constants.js`, `background.js`, `contentScript.js`, `popup.html/js`, `options.html/js`, `stats.html/js`, icons.
3. Manual test pass (local server + prod API): home/search/watch/sidebar/Shorts filtering, flag flows (inline, popup, context menu), shadow mode, placeholder + whitelist, badge, stats, import/export.
4. Chrome Web Store listing: privacy policy URL `https://nottoobright.github.io/ByeAI/privacy/`, support email, updated screenshots (placeholder bar is the money shot).

1. `chore/landing-page` — commit landing page, workflow path fix, privacy/README updates. *(Independent; unblocks Pages immediately.)*
2. `feat/shared-constants` — `constants.js`, de-dupe categories, API URL centralization (placeholder domain), B7/B9/B10, manifest updates.
3. `fix/flags-batching-errors` — B1, B2.
4. `fix/inline-button-churn` — B3.
5. `fix/vote-feedback` — B4, B5, B6.
6. `feat/shorts` — F1 + B8 selector refresh.
7. `feat/placeholder-whitelist` — F2 + F3.
8. `feat/badge` — F6.
9. `feat/server-cold-start` — threshold env vars, view-count lookup change, tests, health version.

Testing: server work is TDD with the existing pytest setup; extension work is verified via the manual test plan in each PR (consistent with v1.3 practice — no JS test framework).

## Appendix A — Infra runbook (user actions)

### A.1 Buy the domain (~5 min)

1. Any registrar works; Porkbun is already familiar. Cheap options: `.xyz`, `.site`, `.top`, `.online` (≈ $1–12/yr; check renewal price, not just year-1).
2. Tell Claude the domain name — it gets wired into `constants.js`, `manifest.json`, and `privacy.md`.
3. Optional: set up the registrar's free **email forwarding**: `support@<newdomain>` → personal Gmail.

### A.2 DNS (~2 min, at the registrar)

- Add one record: `A` | host `api` | answer `152.69.161.151` | TTL default.
- No records needed for the website (it lives on github.io).

### A.3 GitHub repo settings (~2 min)

1. Settings → Pages → **Source: GitHub Actions**. (This is why every deploy failed.)
2. Settings → Pages → **Custom domain: remove `byeai.tech`** (kills the redirect to the dead domain).
3. After the landing-page PR merges, re-run the Pages workflow; verify `https://nottoobright.github.io/ByeAI/` and `/privacy/`.

### A.4 Oracle VPS (~15 min, over SSH)

```bash
# 1. Revive the API (it currently 502s)
sudo systemctl status byeai      # or: gunicorn/uvicorn unit name
sudo journalctl -u byeai -n 50   # find out why it died
cd /opt/byeai && git pull && source venv/bin/activate && pip install -r requirements.txt
sudo systemctl restart byeai && curl -s localhost:8000/health

# 2. Point nginx at the new hostname
sudo sed -i 's/api\.byeai\.tech/api.<NEWDOMAIN>/g' /etc/nginx/sites-available/byeai
sudo nginx -t && sudo systemctl reload nginx

# 3. TLS cert for the new hostname (after DNS propagates)
sudo certbot --nginx -d api.<NEWDOMAIN>

# 4. Cold-start thresholds
echo -e 'VIDEO_THRESHOLD_FLOOR=3\nCHANNEL_FLAG_THRESHOLD=3' | sudo tee -a /opt/byeai/server/.env
sudo systemctl restart byeai

# 5. Verify from outside
curl -s https://api.<NEWDOMAIN>/health
```

### A.5 Surrender byeai.tech

Simply let it expire (no action). Do it only **after** the new API domain is live and v1.4 is released — v1.3 was never published, so no existing users depend on the old domain.
